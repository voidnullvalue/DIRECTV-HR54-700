# HR54 v3 development beachhead

This directory contains the first post-proof payload. It is packaged by `poc-hardware/build-plugin-v3.sh` into the asset-7 signature/path-confusion image.

## Components

- `indexer`: BusyBox-ash wrapper at the path `Mp4libFeatureStarter` executes during normal initialization. Its first action is the primitive persistent root proof. It then starts inventory and services once per boot and finally `exec`s the byte-preserved vendor `indexer.real`.
- `collect-inventory`: writes kernel, CPU, memory-map, interrupt, MTD, module, network, sysfs-path, module-tree, firmware-tree, and dmesg evidence under `/var/hr54-inventory`.
- `hr54d`: 812-byte libc-free MIPS32 big-endian o32 listener generated by `build-hr54d.py`. It listens on TCP/5777, forks per connection, connects the socket to descriptors 0/1/2, and executes `/bin/bash -i` as the already-root caller.
- The launcher also starts the recovered stock `in.tftpd` on UDP/1069 with `/var/hr54-transfer` as its root and file creation enabled.

The launcher inserts explicit IPv4 drops for TCP/5777 and UDP/1069, then places accepts for loopback, RFC1918, and IPv4 link-local sources above them. It does not start either network service unless all firewall commands succeed. There is no application-layer authentication, so use only a trusted private LAN.

## Offline gates passed

- Production `sigtst` accepts the path-confused metadata.
- The recovered MIPS `/bin/sh` executes the launcher's first-action proof and test marker exactly.
- The genuine `libmp4lib.so` and original indexer remain byte-identical; `indexer.real` retains its exit status 22 and expected banner.
- QEMU syscall tracing reached MIPS socket, bind, listen, accept, fork, dup2, and `/bin/bash -i` execve for `hr54d`.
- The recovered TFTP daemon parsed the selected arguments, bound UDP/1069, and daemonized under QEMU.
- The physical v3 image was installed only on dynamically identified partition 2 and independently verified `ro,norecovery`.

Exact hashes, live addresses, and the next research action are in `poc-hardware/STATE.md`.
